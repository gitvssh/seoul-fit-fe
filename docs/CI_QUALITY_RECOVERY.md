# CI 품질 오류 복구 결과

2026-10-19. 공통 개선 작업
[HLG-68](https://youtrack.damecasol.com/issue/HLG-68)에 연결한다. 기본 브랜치는
master, 최초 기준 소스는 bb2269a다. PR #1과 후속 PR #2를 병합한
`04f17fafb87c57512b40ae47e8b7cb17d8435fa4`의 실제 CI가 성공했다.

최근 CI 38123096027은 타입·테스트에 성공했지만 Sonar 신규 품질 문제 178개로
실패했다. 읽기 전용 Sonar 조회에서 전체 미해결 359개와 신규 178개를 구분했다.
80% 커버리지·3% 애플리케이션 중복 기준과 new-code baseline은 유지한다. 후속
데이터 전용 중복 예외는 아래에 범위와 강제 검사를 명시한다.

컴포넌트 입력 85곳을 Readonly로 선언했다. 네이티브 fieldset/output/section으로
기존 접근성 역할을 표현하고 레이아웃 클래스를 유지했다. SDK ref는 실제 fieldset
타입으로 맞췄다. 알림 검사는 명시적 role 속성 대신 실제 접근성 역할을 확인하도록
수정했다. 빈 분기·미사용 import·중복 push·명시적 숫자 변환·선택적 접근·이벤트
타입 이름을 정리했다. 괄호/HTML 문자열 처리는 닫힘 구분자 기준의 선형 처리로
바꿨다. 날씨·혼잡도 API의 캐시 미스 후보 순회를 함수로 분리했으며 요청
순서·캐시·오류 응답·catch 경계는 유지했다.

중첩 조건은 같은 렌더링 순서를 가진 분기로 정리하고 상태 setter 이름을 맞췄다.
SDK와 위치 요청의 중첩 콜백을 분리했다. 검색 팝업 버튼에서 Escape를 누른 뒤
입력창 focus 이벤트가 팝업을 다시 여는 오류를 새 회귀 검사로 확인하고, focus
복구 뒤 닫기 상태를 마지막으로 적용하도록 고쳤다. 지도는 SDK의 키보드 이동
기능이 꺼져 있는 현재 설정에 맞게 비동작 Tab 정지점과 잘못된 방향키 안내를
제거하고 명명된 region으로 노출한다. 확대·축소·현재 위치·장소 선택 버튼은
유지한다.

CI의 의존성 설치와 커버리지 테스트를 한 번만 실행하고 같은 작업공간에서 Sonar를
분석한다. 기존 필수 검사 이름 `SonarQube quality gate`는 동일 실행의 품질 작업
성공과 명시적 검증 완료 출력이 둘 다 있어야 성공한다. 누락·실패·취소는 성공으로
바꾸지 않는다. Actions cache/artifact나 앱 의존성을 추가하지 않았다.

타입 검사, Jest 75개 suite/479개 테스트, 런타임 node 검사와 프로덕션 빌드가
통과했다. 이후 추가한 팝업 포커스 회귀를 포함한 검색 검사 15개도 수정 후
통과했다. ESLint 오류는 0개, 기존 경고는 99개다. 브라우저의 390px/데스크톱
레이아웃에 문서 가로 넘침은 없었다. 로컬 외부 지도 SDK·시설 API 연결은
실패했으므로 실제 지도 데이터/위치 기능의 종단간 성공으로 세지 않는다.

로컬 Sonar 규칙 대조에는 한글 IME의 keyCode 229 호환 처리와 팝업 자식 컨트롤의
이벤트 위임 진단이 남는다. 기존 한글 조합 검사와 새 팝업 focus/Escape 검사는
보존했다. 첫 수정의 실제 재분석 결과와 두 진단의 개별 판단은 아래에 기록했다.
신규 178개 전체를 코드로 해결했거나 원격 CI가 복구됐다고 표시하지 않는다. 인증
자격이나 배포 이미지는 변경하지 않았다.

## 병합 후 실제 검사와 후속 조치

PR #1은 2026-10-19 master `ddf0b0f71408d3601eb3bbc988dc4888b796104a`에 병합됐다.
실제 CI 39224810926은 5분 35초에 실패했다. 기존 신규 진단 178개 중 176개는
재분석에서 사라졌으며, 두 기존 진단과 native region 진단 한 개가 남았다. new
coverage=54.6%(기준 80%), duplication=3.4547%(기준 3%)도 실패 조건이다. 기존
보고를 전체 복구 성공으로 바꾸지 않는다.

두 기존 진단은 동작을 바꾸는 편법 대신 개별 판정했다. 전체 규칙이나 기준값은
유지한다.

- `97214f63-9378-4ed9-8c77-37a4fb350ad5` S6848: false positive. 팝업 wrapper는
  버튼을 대신하는 클릭 대상이 아니라 자식 컨트롤의 focus/Escape를 처리한다.
  네이티브 버튼·listbox·option은 유지한다. 검색 검사에서 한글 입력, 마우스 후
  focus 유지, 버튼의 Escape 뒤 닫기와 focus 복귀를 검증한다.
- `3d0a287f-0952-4fbe-afbb-58f9c5a3f5c7` S1874: accepted compatibility use. IME
  종료 순서에 따라 `isComposing`이 false여도 keyCode=229가 남는다. 이 분기를
  없애면 한글 입력 중 잘못 선택할 수 있다.
  [MDN의 IME 안내](https://developer.mozilla.org/en-US/docs/Web/API/Element/keydown_event#keydown_events_with_ime)와
  기존 실제 keyCode 229 회귀를 근거로 보존했다. blanket NOSONAR·rule 비활성화는
  없다.

후속 준비본에서 map region을 native section으로 바꾼다. Sonar의 테스트 경로를
정식 test scope로 분류하며 테스트 자체의 분석은 유지한다. 번역 키·양언어 소개문
데이터의 반복은 중복 검사에만 좁게 예외를 둔다. 제외된 12개 파일은 TypeScript
AST 검사로 정적 데이터 선언만 허용하고 함수·호출·분기·새 인스턴스 등 실행 로직이
생기면 CI를 실패시킨다. 애플리케이션 로직의 3% 중복 기준과 80% 커버리지 기준은
유지한다. 이 예외는 최초 분석 뒤 실제 중복 위치를 확인해 추가한 데이터 전용
조정이다.

시설 로딩과 부분 오류 복구, 검색·공개 장소 URL과 취소, 위치 권한과 자연어 조건,
지도 컨트롤·마커·모바일 패널, 실시간 정보의 실패·재사용, 상세 화면의 저장·공유,
지하철 도착, 공개 장소의 404·폐관·메타데이터, 관심사 저장·재시도, 알림 메뉴를
실제 훅·UI의 동작으로 검증한다. 네트워크와 외부 SDK 경계만 대체한다.

전체 Jest 634개/90 suite가 약 14초에 통과했다(첫 수정 479개/75 suite). 정적
데이터 범위의 허용/거부 11개, runtime 검사, 타입 검사와 production 빌드도
성공했다. 린트 오류는 0개이며 경고 100개는 남아 있다. API lib/config도 커버리지
수집에 포함해 분석 범위를 맞췄다. 로컬 전체 커버리지와 서버의 신규 코드
커버리지는 다른 지표다.

## 실제 복구 검증

2026-10-19 [master CI 39233390755](https://github.com/gitvssh/seoul-fit-fe/actions/runs/39233390755)는
09:53:11~09:58:38 UTC, 요청부터 최종 필수 검사 완료까지 **5분 27초**에 성공했다.
타입·린트·전체 테스트·runtime·production 빌드·실제 Sonar 분석과 최종 품질 gate가
통과했다. 별도 runner 정책 검사도 성공했다. 이미지 게시 작업은 이 workflow에 없다.

실제 Sonar의 신규 코드 커버리지는 **82.7%**(기준 80%), 중복률은 **0.4235%**(기준 3%),
신규 미해결 진단은 **0개**다. 위 두 진단의 개별 판단과 데이터 전용 중복 예외는
유지하며, 모든 진단을 코드 변경으로 해결했다고 표현하지 않는다. 이번 실행은 10분
기준을 충족했다. 장기 유지나 다른 프로젝트의 CI 성공을 대신하는 근거는 아니다.
